# `tintinweb/pi-subagents` workflow UI research

**Scope.** Read-only comparison of upstream `tintinweb/pi-subagents` with this checkout. Upstream was inspected at the immutable `master` HEAD **`4f572eaa04c09d3dbc16e4a5f13a16b295e84e14`** (2026-08-27, `fix linter warning`). The workflow UI landed in feature commit [`221df02323c6b6350ea8474579e0ee0f6cc84cea0`](https://github.com/tintinweb/pi-subagents/commit/221df02323c6b6350ea8474579e0ee0f6cc84cea0). No production files were changed.

## Upstream UI inventory

- **Persistent activity widget:** [`src/ui/agent-widget.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/agent-widget.ts#L254-L652) renders above the editor. It uses a heading, tree connectors, animated Braille spinner, two lines per running agent (identity/stats plus activity), one-line finished rows, one queued summary, and a 12-line cap. Overflow prioritizes running, then queued, then finished. The widget is registered once and asks the TUI to repaint rather than replacing the widget on every update.
- **FleetView:** [`src/ui/fleet-list.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/fleet-list.ts#L99-L540) is a render-only `belowEditor` widget plus an `onTerminalInput` handler. The roster is `main`, workflow rows, then agents; workflows are containers and are deliberately not interleaved with their children. It shows at most five rows, earliest-launched first, with right-aligned elapsed/token stats and a selected-row marker.
- **Workflow card:** [`src/ui/workflow-card.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/workflow-card.ts#L301-L457) builds a pure, unthemed segment layout: header/counts, optional description, one continuous phase tree, agent status/stat tails, logs, and a large-run warning. `styleWorkflowCardLines` applies theme later. Width clamping preserves the stats tail and keeps every line within the terminal.
- **Workflow inspector:** [`src/ui/workflow-dialog.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/workflow-dialog.ts#L350-L1079) is a centered, framed two-pane overlay. Overview: phases left and selected-phase agents right. Drill-down: agents left and selected-agent Prompt/Activity/Outcome detail right. The frame has a 6-row minimum and 22-row default ceiling; both panes are padded to a fixed height so selection does not make the dialog jump. The left pane is capped at 18 columns so the detail pane gets the space.
- **Conversation viewer:** [`src/ui/conversation-viewer.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/conversation-viewer.ts#L151-L260) is a separate live transcript overlay. It auto-scrolls, bounds tool output at 16,000 characters, caches Markdown components per message, supports an inline steer composer, and has a two-press stop guard.
- **Entry/wiring:** [`src/ui/workflow-menu.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/workflow-menu.ts#L52-L192) injects task/record/action dependencies and uses the same inspector from menu and FleetView. Upstream intentionally has no top-level `/workflows`; its workflow menu is part of `/agents` to avoid command collisions. `src/index.ts` wires the fleet row to `showWorkflowDialog`.

## Keyboard model and hierarchy

- **FleetView:** at an empty prompt, `Down` or `Left` activates the list and consumes the key; `Up/Down` navigate; `Enter` opens; `Esc` or `Up` above `main` returns to the prompt. Any other key deactivates and passes through. Key-release events are ignored to prevent double movement. Focus is checked so selectors/dialogs do not lose their keys. See [`fleet-list.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/fleet-list.ts#L308-L361) and its primary-source tests [`test/fleet-list.test.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/test/fleet-list.test.ts#L201-L416).
- **Workflow inspector:** `j/k` or arrows clamp selection (no wrap); `Enter/Right` descends from phases to agents and then expands the prompt; `Esc/q` backs out one level or closes; `Ctrl+C` closes outright; `f` cycles filters; `x` stops; `p` pauses/resumes; `s` skips; `r` retries; `c` opens the selected child conversation. Hints are derived from actually injected actions, so the footer does not promise unavailable controls. See [`handleWorkflowDialogKey`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/ui/workflow-dialog.ts#L925-L1023).
- **Conversation viewer:** `Enter` opens steer, `x` then `x` confirms stop, `m` cycles raw/assistant Markdown/all Markdown, arrows and page keys scroll, `Home/End` jump, and `Esc/Ctrl+C/q` close. The viewer remains open when a child settles.
- **Visual priority:** identity and state lead; metadata is secondary and right-aligned; detailed prompt/output is only shown after a deliberate drill-down. Selection uses accent/primary text while unselected rows recede. Workflows are visually containers, not another flat child list. The inline card is compact observability; the inspector is control and explanation.

## Upstream state model

`src/workflow/progress.ts` defines an append-only event-like progress array. [`collapse`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/workflow/progress.ts#L151-L184) applies last-write-wins by stable agent index and accumulates logs. `displayState` derives `queued`, `running`, `done`, `failed`, `skipped`, `blocked`, or `interrupted` from raw entry state plus overall run activity. Phase groups and counts are derived, including declared-but-unseen placeholders.

The background record in [`src/workflow/task.ts`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/src/workflow/task.ts#L91-L224) owns run status, append-only progress, counts, pause timing, and terminal outcome. Updates are batched and counters are recomputed from the collapsed view. Child sessions remain owned by the subagent manager; workflow entries carry identifiers/previews, not copied transcripts. Controls are injected into the inspector and map to pause/resume/skip/retry/kill actions.

This model is intentionally simpler than this checkout's workflow authority: it is useful for renderer behavior, but its raw `state` vocabulary and derived display vocabulary must not be conflated.

## Concrete minimal distinct shape: `Ctrl+Shift+Z`

This is the implemented direction. The local surface is a **workflow-only inspector**, not a copy of upstream's FleetView or a renamed `/subagents` dashboard. Lifecycle controls remain tool-authoritative in this slice; the inspector is read-only apart from opening a child view.

1. **Registration/entry:** register `Ctrl+Shift+Z` in `extensions/subagents/index.ts`. In TUI mode, call a new `openWorkflowPicker(ctx, workflowManager, manager.view)`; if there are no runs, notify `No workflow runs yet.` and do not open an empty frame. Keep `/workflows` and existing tools unchanged.
2. **One overlay, two levels:** use a compact centered overlay with a stable two-column frame:
   - **Overview:** left = workflow runs (newest first); right = selected run summary and aggregate counts (`terminal/total`, blocked/ready/queued/running/skipped), status, version, and outcome/recovery.
   - **Tasks:** `Enter` on a run switches to its task list; left = bounded task rows; right = selected task detail (status, attempt number/history, dependencies, ownership/read-only, backend/model/effort, current tool, error). `Esc` returns/ closes; `j/k` clamp; `Enter` drills down. A later slice can add `p`/`r`/`s`/`x` only when the selected operation is legal.
3. **Distinct visual language:** use a small `◆`/`◇` run marker, status words (`READY`, `RUNNING`, `BLOCKED`, `DONE`, `FAILED`, `CANCELLED`), a `vN` version badge, and a compact dependency arrow (`needs:a,b`) rather than upstream's phase-tree glyphs. Put the run title first, status/counts second, and diagnostic metadata third. Right-align counts/times; clamp labels while preserving status and counts. This makes the surface read as a workflow control plane, not another agent transcript.
4. **Pure rendering seam:** create `extensions/subagents/src/ui/workflow-inspector.ts` with pure `resolveWorkflowUiState`, `handleWorkflowUiKey`, and `layoutWorkflowInspector` over `WorkflowProjection`; keep theme application and TUI timers in a thin component. Reuse local `truncateUtf8`/visible-width helpers and the existing `projectWorkflowRun`. Do not copy upstream `WorkflowDialog`, `WorkflowCard`, or Claude Code strings.
5. **Live updates:** subscribe to the workflow manager/read model and child view, coalesce updates at about 100ms, and re-render from a fresh projection. Preserve selected `runId`/`taskId` across updates; clamp when a task/run disappears. Do not add another event bus or another persistence path.
6. **Control authority:** dispatch through `WorkflowControls` (`pause`, `resume`, `retryTask`, `skipTask`, `cancelRun`) and re-project afterward. Do not call `WorkflowManager` internals from UI code. Child transcript access, if later required, should use the existing child id and takeover/viewer seam rather than copying transcript data into the projection.
7. **Responsive fallback:** below a documented width threshold, collapse to one run/task list plus a short selected-summary block; never let a long label hide status, selection, or the way out. Keep the frame height stable while moving selection.

### Patterns to reuse

- Pure layout + themed rendering; bounded width/rows/bytes; right-aligned high-value stats.
- Stable selection by id, clamped after projection changes, and selection-preserving overlay return.
- One aggregate rail item for a workflow, while task detail is obtained only on demand.
- Explicitly truthful key hints, focus ownership, release-event filtering, and render coalescing.
- Separate compact inline observability from deliberate detailed inspection.

### Patterns to avoid

- Do not flatten workflow tasks into the existing agent takeover list: it loses dependency/attempt/ownership semantics and advertises steer/abort where `operatorSubagentView` rejects them.
- Do not make the rail a second workflow UI or publish child rows separately; the current projection intentionally aggregates workflow activity.
- Do not copy upstream's append-only `WorkflowEntry` state model over the local event journal, or copy its phase assumptions into local task statuses.
- Do not expose full transcripts/results in `WorkflowProjection`; local bounds and owner checks are deliberate.
- Do not use mutable captured snapshots, unbounded output, wrapping lines, or per-token widget replacement.
- Do not assume upstream's dependency versions/API surface: upstream declares `@earendil-works/pi-* >=0.84.0` in [`package.json`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/package.json#L23-L27), while this repo develops against `^0.80.7` and has its own Effect/typebox contracts.

## Licensing and provenance caution

Upstream's [`package.json`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/package.json#L1-L8) and [`LICENSE`](https://github.com/tintinweb/pi-subagents/blob/4f572eaa04c09d3dbc16e4a5f13a16b295e84e14/LICENSE) identify an MIT-licensed work (Copyright 2026 tintinweb). MIT permits reuse only with the required copyright/license notice. This note recommends **independent implementation from local contracts**, not copying upstream source, exact UI strings, or Claude Code-derived behavior. If code is ever reused, preserve attribution/license and obtain the project's legal review; do not infer that an upstream MIT label resolves provenance of every borrowed design/string.

## Key conclusions

1. Upstream succeeds by separating three levels: compact persistent activity, navigable fleet, and deliberate workflow inspection. Its strongest reusable mechanisms are focus-safe input, stable selection, bounded fixed layouts, and pure render functions.
2. This checkout already has the more authoritative workflow model and safer projection boundary. The missing piece is a workflow-specific TUI, not a new state model or a broader rail.
3. `Ctrl+Shift+Z` should open a run→task inspector sourced from `projectWorkflowRun`, with local statuses/attempts/dependencies/ownership and `WorkflowControls`. Keep `Ctrl+Shift+A` for subagent takeover and keep existing workflow commands as the text/tool fallback.
4. Implementing that shape independently avoids incompatible upstream APIs, avoids misleading generic child controls, and respects the upstream MIT/attribution boundary.
